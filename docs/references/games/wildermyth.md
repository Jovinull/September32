# Wildermyth

Original analysis. No content from the work is reproduced here.

## USE FOR

**Contextual event selection.** Events chosen because they fit the current cast
and situation, not from a queue.

**Personality driving content.** Characters have traits that determine which
events can involve them.

**Controlled repetition.** Content recurs, and the system manages how often so it
does not read as a loop.

**Relationships between non-player characters** that develop without the player.

## DO NOT COPY

The setting, the tactical layer, the specific event system, the art direction.

## PRINCIPLE

> An event chosen because it fits feels authored. The same event chosen at
> random feels like a slot machine.

## RELEVANCE TO SEPTEMBER 32

The director's selection is this idea. Priority as a hard tier, weight within
it, and repeat damping (halving weight per play) so a repeatable scene is
*available* rather than insistent.

The NPC-to-NPC relationship support is here for the same reason theirs is: the
world should be doing something when the player is not watching.

## RISKS

**Visible seams.** Procedurally-assembled events can read as templates. This
project's answer is that nothing is assembled — every scene is written whole, and
only the *selection* is systemic (ADR-0004).
